# ULPF Live Demo Failure Playbook & Edge-Case Resilience

This document outlines exact system behaviors, automated fallbacks, and judge-facing responses in the event of an edge-case or failure during a live presentation.

---

## 1. Edge-Case Matrix & Recovery Protocols

| Failure / Scenario | Trigger Condition | System Behavior & Fallback | Operator Recovery Action | What to Tell the Judge |
| :--- | :--- | :--- | :--- | :--- |
| **Completely Unparseable / Corrupted Log** | Malformed byte garbage (e.g. `\x00\xff!!` or truncated input). | Falls back to raw preservation without crashing. Stores pristine bytes with SHA-256 in archive; wraps in unstructured OCSF event (`class_uid: 6001`). | System remains responsive; event logged with `parse_status: unmapped_fallback`. | *"ULPF prioritizes lossless forensic preservation above all else. Even when syntax is completely unintelligible, zero raw data is dropped."* |
| **Empty or Whitespace-Only Input** | User pastes blank line or spaces. | Ingestion engine safely rejects with `400 Bad Request` or skips line in streaming generator. | System displays clean validation error; no pipeline crash. | *"The engine validates inputs before allocating parser resources to prevent denial-of-service from empty frames."* |
| **Huge Log Payload (>64 KB)** | Massive multi-kilobyte payload. | Ingestion streams the line, records raw SHA-256, and extracts visible header fields without unbounded buffer expansion. | File written to archive; memory bounded by streaming generator. | *"Our streaming generator processes oversized payloads in memory-safe chunks, protecting workers against out-of-memory crashes."* |
| **Malformed Candidate Source Pack YAML** | Operator edits candidate pack and introduces invalid regex or duplicate keys. | `SourcePackRegistry._validate()` catches syntax error; rejects promotion; logs error; previous pack version remains active. | UI displays `Pack Validation Failed: Invalid Regex`. Active pipeline continues running. | *"The sandbox validation guard prevents operator typos or malformed regex from ever contaminating the runtime registry."* |
| **Zero-Width Evasion in PII** | Adversary injects `\u200B` or `\u200C` inside Aadhaar numbers. | Pre-processing engine strips zero-width Unicode characters; Verhoeff checksum runs on cleaned digits and redacts successfully. | Aadhaar redacted to `[REDACTED_AADHAAR]`. | *"Adversaries frequently insert zero-width characters to evade SIEM regexes. ULPF normalizes Unicode before applying the Verhoeff checksum algorithm."* |
| **Corrupted Threat Intelligence Update** | Malicious actor modifies bytes in offline threat feed. | SHA-256 checksum mismatch triggers instant abort before database write. | UI shows `Threat Intel Bundle Rejected: Integrity Checksum Mismatch`. | *"In sovereign environments, offline updates must be cryptographically verified. Corrupted bundles are rejected before touching local storage."* |
| **Frontend Disconnection / Backend Restart** | Operator accidentally refreshes browser or stops FastAPI daemon. | Restart backend with `python backend/main.py`. Vite hot-module replacement and SSE auto-reconnect restore live stream. | Run `python backend/main.py &` and refresh browser. | *"The architecture decouples the stateless backend API from the browser client; state is persisted in SQLite WAL and JSONL archives."* |
| **External Internet Egress Attempt** | Malicious script or third-party dependency attempts outbound HTTP call. | Kernel socket interceptor raises uncatchable `PermissionError (EPERM)`; connection aborted instantly. | Test passes in `scripts/verify_airgap.py`. | *"Our low-level socket interceptor enforces sovereign air-gap isolation fail-closed. No outbound packet leaves this host."* |
| **Insiders Alter Stored Log Record** | Attacker changes a byte in `storage/lossless_archive.jsonl`. | Merkle leaf recalculation cascades to root; verification API flags `TAMPER_DETECTED: ROOT_HASH_MISMATCH`. | Operator triggers audit via `/api/integrity/verify`. | *"The RFC 6962 Domain-Separated Merkle tree detects single-byte mutations in less than one millisecond, proving non-repudiation."* |
